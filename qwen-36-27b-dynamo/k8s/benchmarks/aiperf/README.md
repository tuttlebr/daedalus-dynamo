# AIPerf Router Demo

This opt-in Kubernetes job runs AIPerf against the in-cluster Dynamo frontend.
It follows the Dynamo router benchmark pattern: generate synthetic prompts,
vary the shared prefix ratio, send OpenAI chat-completions requests, and attach
`nvext.agent_hints` so the KV router can use expected output length and
priority.

Deploy the benchmark job into the same namespace as the Dynamo graph:

```bash
kubectl apply -n qwen36-27b -k k8s/benchmarks/aiperf
kubectl logs -n qwen36-27b job/aiperf-router-demo -f
```

Results are written to the `aiperf-router-demo-results` PVC under
`/results/aiperf-router-demo`, including `summary.json`, `summary.csv`, and
the raw AIPerf artifact directories for each prefix ratio.

To rerun the job:

```bash
kubectl delete job -n qwen36-27b aiperf-router-demo --ignore-not-found
kubectl apply -n qwen36-27b -k k8s/benchmarks/aiperf
```

Default workload (as shipped in `kustomization.yaml`):

- endpoint: `http://qwen36-dynamo-fd-ec-frontend:8000`
- prefix ratios: `0.1,0.5,0.9`
- input/output tokens: `4096/128`
- requests/concurrency: `1000/4`
- prefix prompt pool size: `8`

The script itself defaults `REQUEST_COUNT` to `40` when no env var is supplied;
the shipped overlay overrides that to `1000` for a longer router sweep.

Tune the benchmark by editing the literals in `kustomization.yaml`, then apply
the kustomization again. Useful knobs are `PREFIX_RATIOS`,
`INPUT_SEQUENCE_LENGTH`, `OUTPUT_SEQUENCE_LENGTH`, `REQUEST_COUNT`,
`CONCURRENCY`, `NUM_PREFIX_PROMPTS`, `REQUEST_PRIORITY`,
`SPECULATIVE_PREFILL`, `TOKENIZER_TRUST_REMOTE_CODE`, and
`AIPERF_EXTRA_ARGS`.

## Dynamo agentic hints

The job sends one JSON `--extra-inputs` object that is merged into every
OpenAI chat-completions request. By default it adds:

```json
{
  "ignore_eos": true,
  "nvext": {
    "agent_hints": {
      "osl": 128,
      "priority": 5
    },
    "cache_control": {
      "type": "ephemeral",
      "ttl": "1h"
    },
    "extra_fields": ["worker_id", "timing"]
  }
}
```

`DYNAMO_AGENT_HINTS_DYNAMIC_OSL=true` is enabled by default. The local
`sitecustomize.py` patch updates `nvext.agent_hints.osl` to the actual
per-request `max_tokens` value generated by AIPerf, so runs with non-zero
output-token standard deviation still send accurate expected-output-length
hints.

Useful Dynamo-specific knobs:

- `DYNAMO_AGENT_HINTS_ENABLED` toggles the `nvext.agent_hints` object.
- `USE_EXPECTED_OSL` toggles `agent_hints.osl`.
- `REQUEST_PRIORITY` sets `agent_hints.priority`; set it empty to omit.
- `SPECULATIVE_PREFILL=true` adds `agent_hints.speculative_prefill`.
- `DYNAMO_AGENT_HINTS_JSON` merges arbitrary extra hint fields.
- `DYNAMO_EXTRA_FIELDS` controls requested Dynamo response metadata.
- `CACHE_CONTROL_TTL` sets ephemeral cache-control TTL; set empty to omit.
- `DYNAMO_CACHE_CONTROL_JSON`, `DYNAMO_NVEXT_JSON`, and
  `DYNAMO_EXTRA_INPUTS_JSON` provide JSON object overrides for advanced cases.
- `DYNAMO_IGNORE_EOS=false` omits the root `ignore_eos` request field.

`AIPERF_PATCH_DYNAMO_STREAM_EVENTS=true` is enabled by default. It installs a
small `sitecustomize.py` compatibility patch for AIPerf so Dynamo's named SSE
side-channel events, such as `reasoning_dispatch`, do not fail AIPerf's strict
OpenAI chat parser. Disable it only after AIPerf natively supports those Dynamo
streaming events.

`AIPERF_PATCH_DYNAMO_AGENT_HINTS=true` controls the dynamic OSL patch described
above. Disable it only if AIPerf gains native per-request support for Dynamo
agentic hints.

The job installs `aiperf==0.7.0` from PyPI at startup. Override
`AIPERF_PIP_SPEC` if you want to test a different release or Git ref, for
example:

```text
AIPERF_PIP_SPEC=git+https://github.com/ai-dynamo/aiperf.git
```
